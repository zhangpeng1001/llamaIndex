# RAG 实践笔记

RAG 是 Retrieval-Augmented Generation，即检索增强生成。离线阶段先加载资料、切块、计算向量并建立索引；在线阶段把用户问题向量化，找出最相似的 Top-K 文本块，再让 LLM 依据这些上下文回答。

RAG 的关键优势是知识可以独立更新，不必每次微调模型；回答还可以携带 source_nodes，帮助用户追溯证据。但检索结果并不自动保证正确，应用应该展示来源，并在没有充分证据时允许模型明确说不知道。

切块太大会混入无关信息并消耗上下文窗口，切块太小又可能破坏语义。Top-K 太小可能漏掉证据，太大则增加噪声和模型费用。生产系统应使用自己的问题集评估参数，而不是盲目照搬默认值。

metadata 可保存文件名、部门、日期、权限等级等信息。MetadataFilters 可以先按权限或业务范围过滤，再做向量相似度检索。这是多租户知识库中非常重要的安全边界，但权限校验还应在应用层和数据层同时执行。
