RAG 问答：带来源的规范条款问答

完整走一遍"检索 → 合成 → 输出来源"。问题会匹配到最相似的规范条款并由模型作答。

向量检索：只检索不生成

只调用向量检索，展示 Top-K 节点与相似度分数，便于调试检索质量。可按文件名过滤。

按部分检索：限定规范某一部分

规范共 7 部分，选择部分编号后只在该部分范围内检索，避免跨部分噪声。

全文总结：遍历全部规范做归纳

使用 SummaryIndex + tree_summarize 遍历 7 部分全部条款做归纳，而非只取相似块。

流式回答：SSE 逐字推送

通过 Server-Sent Events 逐 token 推送生成结果，适合长回答场景。

异步查询：非阻塞 RAG

演示 aquery 接口，Web 服务中应优先使用异步避免阻塞事件循环。

使用说明

启动方式

# 默认 local 模式（无需 API Key），端口 8001
python -m qualityScheme.web

# 指定端口
python -m qualityScheme.web --port 8080

# 使用 OpenAI 真实模型并重建索引
python -m qualityScheme.web --provider openai --rebuild

数据来源

数据源位于 qualityScheme/data/，由 standard/ 目录下的 7 份 PDF 规范文档提取而来：

  • 第1部分 数据分类与基本规定
  • 第2部分 检测点
  • 第3部分 检测线
  • 第4部分 标志性地物
  • 第5部分 重要要素
  • 第6部分 高精度栅格数据
  • 第7部分 资源数据

功能与代码对应

  • RAG 问答 ↔ query_engine.py
  • 向量检索 ↔ metadata_filter.py
  • 按部分检索 ↔ metadata_filter.py/retrieve_by_part
  • 全文总结 ↔ summary_engine.py
  • 流式回答 ↔ query_engine.py (streaming=True)
  • 异步查询 ↔ query_engine.py (aquery)

模块清单

  • document_loader.py — 文档加载 (SimpleDirectoryReader)
  • document_parser.py — 数据摄取 (IngestionPipeline)
  • vector_index.py — 向量索引 (VectorStoreIndex)
  • index_persistence.py — 索引持久化 (StorageContext)
  • query_engine.py — RAG 问答 (QueryEngine)
  • source_tracker.py — 来源追踪 (source_nodes)
  • metadata_filter.py — 元数据过滤 (MetadataFilters)
  • summary_engine.py — 全文总结 (SummaryIndex)

注意事项

  • 首次启动会构建索引并持久化到 qualityScheme/storage/，之后自动加载。
  • 修改 qualityScheme/data/ 中的材料后，点击右上角"重建索引"。
  • local 模型的回答是确定性的抽取式结果，仅用于观察框架流程。
  • OpenAI 模式回答更自然，但会消耗 API 额度。
