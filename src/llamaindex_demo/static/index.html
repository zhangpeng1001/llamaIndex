Quickstart：带来源的 RAG 问答

完整走一遍“检索 → 合成 → 输出来源”。默认问题来自 README。

Retrieve：只检索不生成

只调用向量检索，展示 Top-K 节点与相似度分数，便于调试检索质量。

Chat：带记忆的多轮对话

基于 ChatEngine + Memory，会话保存在服务端内存。刷新或重建索引会清空。

session: （未创建）

Summary：全文总结

使用 SummaryIndex + tree_summarize 遍历全部材料做归纳。

Router：向量问答 vs 全文总结

离线模式按关键词确定性路由；OpenAI 模式由 LLM 选择工具。

Structured：Pydantic 结构化输出

把自然语言材料转为经 Pydantic 校验的 KnowledgeCard。

Stream：流式输出（SSE）

通过 Server-Sent Events 逐字符推送生成结果。

Async：异步 QueryEngine

演示 aquery 接口，Web 服务中应优先使用异步避免阻塞事件循环。

Workflow：事件驱动 RAG

用 Workflow 的 StartEvent → RetrievedEvent → StopEvent 显式编排检索与生成。

Agent：工具调用（OpenAI 限定）

让支持 function calling 的模型自主决定是否调用知识库工具。需要 --provider openai。

Evaluate：检索评估

对黄金问题集计算 Hit Rate 与 MRR，不调用 LLM，结果可复现。

使用说明

启动方式

# 默认 local 模式（无需 API Key）
llama-demo web

# 指定端口
llama-demo web --port 8080

# 使用 OpenAI 真实模型并重建索引
llama-demo --provider openai --rebuild web

对应关系

  • Quickstart ↔ llama-demo quickstart
  • Retrieve ↔ llama-demo retrieve
  • Chat ↔ llama-demo chat
  • Summary ↔ llama-demo summary
  • Router ↔ llama-demo router
  • Structured ↔ llama-demo structured
  • Stream ↔ llama-demo stream
  • Async ↔ llama-demo async
  • Workflow ↔ llama-demo workflow
  • Agent ↔ llama-demo agent（需 OpenAI）
  • Evaluate ↔ llama-demo evaluate

注意事项

  • 首次启动会构建索引并持久化到 storage/，之后自动加载。
  • 修改 data/ 中的材料后，点击右上角“重建索引”。
  • local 模型的回答是确定性的抽取式结果，仅用于观察框架流程。
  • 多轮对话会话保存在进程内存中，重启服务后会清空。
