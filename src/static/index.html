流程:分阶段操作(Loading → Indexing → Storing)

按顺序执行三大阶段,每阶段可单独运行并查看统计。也可点击底部"一键重建索引"顺序执行全流程。 完成后即可在 RAG 问答 / 向量检索 / 方案编排 等面板中使用。

1加载文档(Loading)
2切块索引(Indexing)
章节感知切块(384/64)+ 嵌入 + Node JSON 导出
3写入 Milvus(Storing)
一键全流程:从 standard PDF 重新提取 → 切块嵌入 → 写入 Milvus(rebuild collection)。 适合首次构建或规范文档更新后使用。

RAG 问答:带来源的规范条款问答

完整走一遍"检索 → 合成 → 输出来源"。问题会匹配到最相似的规范条款并由模型作答。

向量检索:只检索不生成

只调用向量检索(Hybrid: Dense + BM25),展示 Top-K 节点与相似度分数,便于调试检索质量。可按文件名过滤。

按部分检索:限定规范某一部分

规范共 7 部分,选择部分编号后只在该部分范围内检索,避免跨部分噪声。

全文总结:遍历全部规范做归纳

使用 SummaryIndex + tree_summarize 遍历 7 部分全部条款做归纳,而非只取相似块。带两级缓存(answer + nodes, TTL 1h)。

流式回答:SSE 逐字推送

通过 Server-Sent Events 逐 token 推送生成结果,适合长回答场景。

异步查询:非阻塞 RAG

演示 aquery 接口,Web 服务中应优先使用异步避免阻塞事件循环。

方案编排:自然语言生成质检方案

输入一句自然语言质检需求,系统会检索时空数据规范作为上下文,自动从预定义检查项清单中 选择匹配项并推断参数,生成结构化质检方案。生成的 checkCode 必须来自清单。

使用说明

启动方式

# 默认 local 模式(需 Ollama),端口 8082
python -m src.server

# 指定端口
python -m src.server --port 8082

# 使用 OpenAI 真实模型
python -m src.server --provider openai

分阶段操作流程

新版采用分阶段设计,启动后不自动构建索引。请在"流程"面板按顺序操作:

  • Step 1 加载文档(Loading):从 PDF 提取增强 MD 或读取已有 MD,生成带富 metadata 的章节级 Document
  • Step 2 切块索引(Indexing):章节感知切块(384/64)+ 嵌入,并按源文档导出 src/node/*.json
  • Step 3 写入 Milvus(Storing):创建 MilvusVectorStore + 写入规范 Nodes + manifest
  • 或点击 一键重建索引 顺序执行三阶段(rebuild collection)

注:若 Milvus 已有数据,启动时会自动加载 index,可直接使用查询功能无需重建。

数据来源

数据源位于 standard/ 目录下的 7 份 PDF 规范文档(增强提取后写入 src/data/):

  • 第1部分 数据分类与基本规定
  • 第2部分 检测点
  • 第3部分 检测线
  • 第4部分 标志性地物
  • 第5部分 重要要素
  • 第6部分 高精度栅格数据
  • 第7部分 资源数据

功能与代码对应

  • 流程 ↔ loading.py / indexing.py / storing.py
  • RAG 问答 ↔ querying.py(make_engine)
  • 向量检索 ↔ querying.py(run_querying) (Hybrid: Dense+BM25)
  • 按部分检索 ↔ querying.py(retrieve_by_part)
  • 全文总结 ↔ summary.py(SummaryIndex + tree_summarize)
  • 流式回答 ↔ querying.py(streaming=True)
  • 异步查询 ↔ querying.py(aquery)
  • 方案编排 ↔ scheme.py(查询分解+TopN候选+Pydantic)

src 模块清单

  • config.py — 配置加载(复用 qualityScheme.config,路径指向 src/data)
  • models.py — 模型配置(Ollama/OpenAI)
  • state.py — RuntimeState 跨阶段共享状态 + Summary 缓存
  • loading.py — Loading 阶段:PDF→MD→Document
  • indexing.py — Indexing 阶段:切块+嵌入+Node JSON 导出
  • storing.py — Storing 阶段:Milvus 写入 + manifest
  • querying.py — Querying 阶段:Hybrid 检索 + QueryEngine
  • summary.py — 全文总结(SummaryIndex + 两级缓存)
  • scheme.py — 质检方案生成(意图识别+查询分解+Pydantic)
  • server.py — FastAPI 入口(端口 8082,14 个 API 端点)

注意事项

  • 首次启动无索引数据,需在"流程"面板执行三阶段,或点击"一键重建索引"
  • local 模式需先启动 Ollama 并拉取模型(qwen2.5:7b + nomic-embed-text)
  • OpenAI 模式回答更自然,但会消耗 API 额度
  • 修改 standard/ 中的 PDF 后,需点击"一键重建索引"
